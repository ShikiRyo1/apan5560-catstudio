# Recorded experiment

These records describe the completed CatStudio run, not an expected result. `training_summary.json` identifies the full training budget and selected checkpoint. `evaluation_summary.json` summarizes all 64 matched pairs; `per_image_metrics.json` retains the per-output measurements and relative artifact paths. `resume_equivalence.json` retains the failed strict numerical test.

The repository includes two illustrative pairs, p03 and p15 at seed 101, selected before outputs were inspected. The complete 128-image grid can be regenerated from `config/evaluation_plan.json` and the released adapter using the documented evaluation script. Paths beginning `04_Data`, `05_Models` or `06_Results` are paths relative to the project parent, not files promised inside this small results folder.

Scores are automated CLIP proxies. Intervals use paired prompt-cluster bootstrap, not 128 independent observations. The trained model is not presumed to outperform base on every metric. See `MODEL_CARD.md` for actual values, intended use and limitations. `deployment_lora.json`, `docker_context.json` and `lora_seed42_steps20.png` record the real local Docker query, retaining the exact report and response-image bytes. The Docker receipt retains only runtime identity, settings and source hashes, with no host mount paths or environment secrets. Figure-source provenance and packaged figure hashes are also retained. No Canvas materials or student roster are included.

`visual_review_protocol.json` and `visual_review.json` record the fixed 32-image, single-reviewer AI-assisted audit; `nearest_training_visual_review.json` records the separate 16-pair similarity screen. `report_findings.md` explains observed gains and failures, including loss of pose control despite a slightly higher automated pose proxy. These are not human preference ratings. `resource_measurements.json` gives the tested host/Docker memory context and the measured container lifetime peak; it is not a minimum-RAM guarantee.
